## Known Risk

- WebRTC peer latency could cause AI enemy desync in PvE mode. Mitigation: Host is sole authoritative simulator for enemies and broadcasts snapshots to clients.
- Packet injection from clients. Mitigation: `HOST_ONLY_EVENTS` filtering and host early return guard clauses.

---

## Decisions

### D-1: Unified Leaderboard with ⚔️ Badge
- Decision: Record multiplayer PvP scores in the main `tanks` D1 table with `⚔️ MP PvP` prefix in the `detail` column.
- Reason: Keeps all arcade competition visible without schema fragmentation.
- Impact: Leaderboard modal displays a dedicated `⚔️` icon next to multiplayer entries.

### D-2: Friendly Fire Disabled in PvE Squad Mode
- Decision: Player bullets pass cleanly through ally tanks without damage, and teammates do not trigger ally mines.
- Reason: Accessible, enjoyable co-op party gameplay on smartphones.

## Security Findings

- Zero credentials, secrets, or API keys committed or logged.
- WebRTC DataChannel Star Topology: Host-authoritative physics simulation prevents client-side god-mode, teleportation, or forged bullet damage.
- `HOST_ONLY_EVENTS` set added to NetworkManager.js blocking non-host clients from forging host-only events (`match-over`, `pong-match-over`, `squad-victory`, `squad-defeated`, `pve-wave-complete`, `pve-level-start`, `return-to-lobby`).
- Host unconditionally ignores incoming `network-event` in `MultiplayerTanks.js:2104`.
- Rate limiting on firing inputs: 220ms bullet cooldown, 1000ms mine cooldown, max 3 enemy mines.
